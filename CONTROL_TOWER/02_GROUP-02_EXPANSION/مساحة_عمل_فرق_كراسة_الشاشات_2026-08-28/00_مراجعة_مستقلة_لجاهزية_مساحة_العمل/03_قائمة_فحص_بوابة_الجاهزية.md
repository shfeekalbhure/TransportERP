# قائمة فحص بوابة الجاهزية قبل إطلاق الفرق

لا يعتبر أي بند ناجحًا إلا بدليل فعلي.

## 1. مساحة العمل
- [ ] README واضح ومحدث.
- [ ] قرار المالك موجود.
- [ ] الكراسة الرئيسية موجودة ويمكن قراءتها.
- [ ] فهرس المراجع موجود.
- [ ] أوامر الفرق موجودة.
- [ ] مسارات التقارير موجودة.
- [ ] مسار المراجعة المستقلة موجود.
- [ ] التصميم البصري محجوب حتى الاعتماد.
- [ ] التجميع والمصالحة لهما مسار واضح.

## 2. كل فريق 01–08
- [ ] تعريف الفريق.
- [ ] أعضاء الفريق بالصفات.
- [ ] نطاق محدد.
- [ ] مراجع محددة.
- [ ] ممنوعات واضحة.
- [ ] اعتماديات واضحة.
- [ ] تقرير باسم ومسار محددين.
- [ ] قاعدة منع التخمين.
- [ ] قاعدة عدم تعديل الأصل.
- [ ] أمر إطلاق قابل للفهم من محادثة مستقلة.

## 3. التداخل والفجوات
- [ ] لا توجد مهمة حرجة بلا مالك.
- [ ] لا يوجد تكرار يؤدي إلى تعديل متعارض.
- [ ] التداخل المقصود بين الفرق موضح.
- [ ] لا توجد دورة اعتماد دائرية.

## 4. النطاق
- [ ] النقل والركاب والبوالص والشحن والتوصيل مغطاة.
- [ ] الخفيف والمتوسط والثقيل مغطى.
- [ ] الحسابات المرتبطة بالنقل مغطاة.
- [ ] الموارد البشرية العامة والصيانة خارج النطاق إلا للارتباط المباشر.
- [ ] الشاشات المساندة والتقارير والطباعة والتهيئة والإعدادات والنوافذ مغطاة في الحصر.

## 5. المراجع
- [ ] كل إحالة داخلية تشير إلى ملف/مسار موجود.
- [ ] لا يوجد اسم قديم أو مسار مكسور يؤدي لتوقف الفريق.
- [ ] المسح الخارجي يطلب مصادر وأدلة.
- [ ] ممنوع النسخ الأعمى من الأنظمة الخارجية.

## 6. Git والحوكمة
- [ ] branch workspace معروف.
- [ ] branch Control Tower معروف.
- [ ] نقطة الاشتقاق موثقة.
- [ ] الانحراف الحالي مقاس.
- [ ] أثر الانحراف مصنف.
- [ ] لا merge/rebase/cherry-pick/force-push ضمن المراجعة.

## 7. الحكم
لا تصدر `PASS` مع وجود BLOCKER مفتوح.

إذا كان هناك HIGH غير مغلق، يجب تفسير سبب عدم اعتباره BLOCKER قبل السماح بالإطلاق.
