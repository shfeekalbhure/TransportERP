# تكليف إعادة المراجعة المستقلة — AuditEvent وSyncOperation

**المشروع:** TransportERP  
**التاريخ:** 2026-08-19  
**المرجع:** تقرير `P1_AUDIT_SYNC_CORRECTIVE_ACTION_REPORT_2026-08-19.md`  
**الحالة:** تكليف مراجعة مستقل؛ لا يمثل قرار PASS.

## الغرض

يُكلّف فريق المراجعة المستقل بإعادة فحص الإصلاحات المنفذة لإغلاق ملاحظات تقرير FAIL السابق لخدمتي AuditEvent وSyncOperation. يعمل الفريق خارج منفذ التنفيذ، ولا يعتمد على تأكيدات المطور أو نتيجة البناء وحدها، بل يعيد تشغيل الأدلة ويطابقها بالعقود الحاكمة.

## استقلال الفريق

لا يشارك أعضاء فريق المراجعة في كتابة الكود أو تعديل الاختبارات أو إعداد Migration محل القرار. يحق للفريق طلب دليل إضافي، وإعادة تشغيل الاختبارات، ورفض أي بند لا يمكن ربطه بملف أو اختبار أو نتيجة PostgreSQL قابلة للتحقق.

## نطاق الفحص الإلزامي

| المحور | الفحص المطلوب |
|---|---|
| AuditEvent | مراجعة Outcome وcanonical Hash، والتحقق من Hash-chain على بيانات جديدة. |
| Append-only | تنفيذ UPDATE وDELETE مباشر على `transport_erp.audit_events` وإثبات الرفض من PostgreSQL. |
| ConflictCase | التحقق من الكيان والجدول والعلاقة والفهرس الفريد والحقول والـstatus constraint. |
| SyncOperation | فحص الحالات والانتقالات، وعدم وجود `RETRIED` كحالة مستقلة. |
| Retry | التحقق من RetryCount وNextRetryAt وExponential Backoff واستنفاد الحد. |
| Idempotency | إعادة إرسال نفس DeviceId + ClientOperationId بنفس Hash وبـHash مختلف. |
| Security | شركة خاطئة، فرع خاطئ، جهاز غير مسجل، مستخدم مختلف، وصلاحية مفقودة. |
| API | فحص `POST /api/v1/sync/operations:batch` ونطاق claims والنتيجة لكل عملية. |
| Migration | تطبيق المخطط من قاعدة فارغة ثم رجوع وصعود Migration دون فقد غير معلن. |
| Regression | تشغيل كامل اختبارات TransportERP.Tests وتسجيل العدد والنتيجة. |

## شروط PASS

يصدر الفريق `PASS` فقط إذا كانت كل البنود الإلزامية قابلة لإعادة التشغيل، وكانت النتيجة الكاملة للاختبارات ناجحة، ولم توجد ملاحظة حرجة مفتوحة، وثبت أن حماية append-only على مستوى PostgreSQL لا تعتمد على EF Core فقط، وأن عزل الشركة/الفرع والجهاز والصلاحية مشتق من سياق الخادم، وأن إعادة المحاولة لا تستخدم `RETRIED`.

## شروط FAIL

يصدر الفريق `FAIL` عند وجود أي فجوة في trigger أو Migration أو idempotency أو العزل أو ConflictCase أو Backoff أو API، أو عند تعذر إعادة تشغيل دليل حرج، أو عند وجود اختلاف بين الكود والعقد، أو عند اكتشاف أن Claims الأمنية يمكن إنشاؤها من جهاز العميل دون موفر هوية موثوق.

## مخرجات الفريق

يجب أن يسلّم الفريق تقريرًا يتضمن قائمة الملفات والعقود التي راجعها، الأوامر التي شغّلها، نتائج الاختبارات، الأدلة المباشرة من PostgreSQL، الحالات غير المغطاة، والقرار النهائي `PASS` أو `FAIL`. إذا كان القرار `FAIL`، يمنع فتح PR ويجب إنشاء مصفوفة إجراءات تصحيحية جديدة قبل إعادة المراجعة.

## بوابة الدمج

> لا يُفتح PR ولا يُدمج أي تغيير من هذا الفرع قبل إرفاق تقرير الفريق المستقل بقرار `PASS` وتوقيع المراجع المسؤول.
