## 5. Quantity invariants

1. Release net quantity may never exceed original WaybillItem quantity.
2. Allocation net quantity may never exceed released remaining quantity.
3. One item may be split across multiple trips.
4. Reversing an allocation never edits/deletes accepted load history.
5. Loaded net quantity may never exceed allocation remaining quantity.
6. Quantity-changing commands are serialized and idempotent using stable `ClientOperationId`.
7. Negative derived balances are blocking integrity failures, never display-only warnings.

## 6. Trip / Manifest invariants

1. Trip execution is a transport/cost source; it does not create new Waybill revenue.
2. VehicleId and DriverId remain governed references until Fleet implementation; C does not create Fleet domain tables.
3. Manifest lines derive from valid active allocations.
4. Manifest cannot finalize while a line is invalid or blocked.
5. Driver handover cannot occur before `FINALIZED`.
6. Trip cannot start before manifest handover/acceptance.
7. LOAD and DEPART movement evidence is append-only. C does not implement ARRIVE/UNLOAD/REALLOCATE/DELIVER events.
8. Starting a relay trip never creates duplicate freight revenue.

## 7. Explicit exclusions / FAIL conditions

FAIL C if it introduces any of:

- arrival receipt/finalization or unload/reallocation runtime;
- warehouse holding runtime beyond future contract references;
- customs clearance runtime;
- delivery/POD/COD;
- commission accrual, TripSettlement or financial close;
- GPS/Fleet entities or raw GPS event ingestion;
- notification/exception-resolution runtime;
- direct Desktop database access;
- updates/deletes of accepted release/allocation/load/movement ledger rows.
