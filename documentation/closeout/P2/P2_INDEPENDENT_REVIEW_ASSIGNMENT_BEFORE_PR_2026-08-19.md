**نقطة الأساس:** `master` عند `e8e22de26b4faa5040f53582ab2c8934d43216f0`  
**حالة التكليف:** `PRE_PR_GATE`  
**تاريخ التكليف:** 2026-08-19 UTC+3

## أمر التكليف

يُكلّف فريق مستقل بمراجعة أي نطاق P2 بعد اعتماد المجال من مالك المشروع وقبل فتح PR تنفيذي. لا يجوز للفريق المنفذ مراجعة نفسه، ولا يجوز اعتبار نجاح P1 أو وثائق المرشحات اعتمادًا لنطاق P2. يجب تسجيل head الذي يراجعه الفريق، ومطابقته مع GitHub قبل بدء الفحص.

## حدود المراجعة

يبدأ الفريق من baseline P1 فقط، ويفحص المجال المختار وحدوده واستبعاداتـه ومصادره وعقوده. يجب أن يتأكد من أن كل حقل وسلوك وشاشة وتكامل له مصدر أو قرار مالك موثق، وأنه لا توجد إضافة تشغيلية مبنية على التخمين.

## معايير القرار

يصدر الفريق قرارًا واحدًا فقط: `PASS` أو `FAIL`. لا يُسمح بـ`PASS_WITH_NOTES` كتفويض للدمج. يصدر `FAIL` عند وجود عقد مفتوح حاكم، أو تعارض traceability، أو دليل مؤقت غير قابل للتدقيق، أو فشل اختبار، أو تحذير بناء حاكم، أو توسع غير معتمد، أو عدم إثبات العزل والأمن.

## الأدلة المطلوبة

يجب تسليم تقرير مستقل، وسجل أوامر قابل لإعادة التشغيل، وسجلات البناء والاختبارات والفحوص، ونتائج Migration، وفحص الأسرار والتبعيات، و`MANIFEST_SHA256`، مع ربط كل ملف بالـSHA الذي فُحص. لا تُقبل مخرجات `/tmp` وحدها كحزمة إغلاق.

## حظر الدمج

يبقى PR مغلقًا أمام الدمج حتى يصدر `PASS` صريح، ثم يعتمد مالك المشروع التقرير على الـhead نفسه. إذا تغير head أو تغيرت العقود أو فشل أي فحص، تُلغى النتيجة ويجب إعادة المراجعة.
