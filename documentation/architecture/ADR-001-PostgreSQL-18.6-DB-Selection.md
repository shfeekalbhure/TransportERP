# ADR-001 — اعتماد PostgreSQL 18.6 لقاعدة بيانات TransportERP

**الحالة:** `ACCEPTED_BY_OWNER`  
**التاريخ:** 2026-08-19  
**النطاق:** محرك قاعدة البيانات الإنتاجي لنظام TransportERP  
**القرار:** اعتماد PostgreSQL 18.6، مع PostGIS للمتطلبات المكانية بعد تثبيت إصدار الامتداد المتوافق في بيئة الإنتاج.

## القرار

بعد تنفيذ بروتوكول POC-14 ومراجعة الأدلة الخام وإعادة حساب نتائج الحمل، يعتمد المشروع PostgreSQL **18.6** بوصفه محرك قاعدة البيانات الإنتاجي. لا يمثل هذا القرار اعتمادًا لمخطط بعينه أو ترحيلات بعينها؛ بل يفتح بوابة تصميم Physical Schema وEF Core Migrations وفق عقود W1 وW2 وW3 المغلقة.

## أساس القرار

أُجريت المقارنة بين PostgreSQL 18.6 وMySQL 8.4.11 في بيئتين معزولتين، باستخدام بيانات اصطناعية ثابتة، وإعدادات تشغيل موثقة، ونتائج خام قابلة لإعادة التحليل. نجح المحركان وظيفيًا في الجولة التجريبية، ولم تسجل عينات الحمل البالغ عددها 312 عينة أي أخطاء خروج. في اختبار الحمل المعتمد، كان PostgreSQL أقل في p95 من MySQL في L1 وL2 وL3.

| المستوى | PostgreSQL 18.6 p95 | MySQL 8.4.11 p95 |
|---|---:|---:|
| L1 | 160 ms | 413 ms |
| L2 | 2,428 ms | 12,328 ms |
| L3 | 6,639 ms | 67,292 ms |

النتيجة لا تعني أن PostgreSQL أفضل بصورة عامة لكل نظام، بل تعني أنه الأنسب لمتطلبات TransportERP المقاسة في POC-14. وقد بقيت حدود الاختبارات الموزعة والأمنية والاستعادة تحت حمل الإنتاج موثقة كقيود تشغيلية يجب معالجتها في مراحل التنفيذ والاختبار التالية.

## القيود والالتزامات

يجب استخدام PostgreSQL 18.6 أو إصدار رقعي أحدث معتمد عبر إدارة تغيير صريحة؛ ولا يجوز القفز إلى إصدار رئيسي آخر داخل هذا القرار. يجب تثبيت إصدار PostGIS المتوافق مع إصدار PostgreSQL في سجل البيئة. كما يجب تنفيذ العزل متعدد الشركات والفروع، وسجل التدقيق، وSyncOperation، والقيود المحاسبية داخل التطبيق والمخطط وفق العقود، دون الاعتماد على سلوك غير موثق أو خصائص خاصة غير مسجلة.

يبقى هذا القرار منفصلًا عن اعتماد بيانات الإنتاج الفعلية. لا تُستخدم بيانات زبائن حقيقية في الاختبارات الأولية، ويجب وضع خطة نسخ احتياطي واستعادة وترحيل وتراجع قبل الإطلاق.

## بوابة التنفيذ التالية

بعد اعتماد هذا ADR، يسمح المشروع بالانتقال إلى:

`W1/W2/W3 contracts` → `Physical Schema` → `EF Core Migrations` → `P1 production implementation`.

لا يسمح هذا السجل وحده بترحيل قاعدة إنتاج أو تشغيل Migration على بيئة إنتاج. كل Migration يجب أن تمر باختبارات بناء وتطبيق وتراجع على بيئة اختبار مؤقتة قبل استخدامها.
