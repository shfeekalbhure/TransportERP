## ANALYSIS — TEAM-D01 PASS
Purpose: manage overrides for a fixed system-owned catalog of operational properties, display local/effective values and provenance, and enforce exact allowed scope resolution.

Canonical data/presentation model:
- `PropertyCode` — read-only canonical key.
- `PropertyLabelAR`, `PropertyLabelEN` — localized/catalog display projections only; no new W1 columns.
- `Group` — read/filter metadata.
- `ValueType` — read-only type metadata.
- `LocalValue` — dynamic editor by ValueType at selected scope.
- `EffectiveValue` — server-resolved read-only value.
- `EffectiveSource` — User/Branch/Company/System/Built-in Default.
- `OverrideState` — Inherited/Overridden/Default.
- `ScopeType` — System/Company/Branch/User subject to AllowedScopes.
- `ScopeId` — conditional authorized scope identifier; null for System.
- `EffectiveFrom`, `EffectiveTo` — optional override dates where contract allows.
- `Version` — hidden expectedVersion token.

The system-owned property catalog contains exactly the 24 closed properties from the governing closure; no free PropertyCode creation.

## FIELD_GRID — TEAM-D03 PASS
Primary editable business grid: `N/A`; this is a scoped Settings editor.
Definition filters: `Group`, `PropertyCode`.
Effective-read inputs: selected `PropertyCodes` and authorized `ScopeType/ScopeId`.

## UX — TEAM-D04 PASS
- `View`: load only system-owned definitions and server-resolved effective values for authorized target scope.
- NearestOverride display order is server-resolved `User → Branch → Company → System → Built-in Default`; UI displays EffectiveSource rather than recomputing ownership.
- `Set/Replace Override` is enabled only when `GEN015.EditSettings` AND matching scope permission AND authorized target scope AND PropertyAllowedScope all hold.
- Matching scope permissions: System=`GEN015.EditSystemScope`; Company=`GEN015.EditCompanyScope`; Branch=`GEN015.EditBranchScope`; User/self=`GEN015.EditOwnPreferences`.
- User scope is self-only under current authority; no other-user mutation.
- `ResetToInherited` uses the same authorization intersection, deletes only the local override, then reloads/reveals inherited effective value; no copy-down.
- stale expectedVersion uses shared concurrency conflict + Reload/Refresh; no silent overwrite.
- unknown/free PropertyCode is rejected; client cannot extend AllowedScopes.
- successful set/reset uses shared audit with actor/scope/property/before-after/effective context/correlation identity.
- connectivity/sync settings do not grant offline authority to modules that do not already support Offline.
- no Print/Export/free setting-key creation or new offline-sensitive capability.
