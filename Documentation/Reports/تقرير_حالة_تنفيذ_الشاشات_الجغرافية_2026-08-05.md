# تقرير حالة تنفيذ الشاشات الجغرافية — TransportERP

**التاريخ:** 2026-08-05  
**الفرع:** `setup/initial-solution-structure`

## الملخص التنفيذي

تم الوصول إلى مرحلة ربط وتشغيل أولي لثلاث شاشات جغرافية داخل الشاشة الرئيسية، مع تصحيح عدد من الأسماء البرمجية ومعالجة تعارضات الموارد ومشكلة اختفاء تذييل بيانات الإنشاء والتعديل.

الحالة الحالية ليست إغلاقًا نهائيًا للمجموعة الجغرافية؛ فما زال يلزم اختبار بناء وتشغيل محلي شامل، ومراجعة شاشة الدول والمدن، وإكمال أعمدة الجداول والسلوك التشغيلي والاختبارات.

## المنجز

### 1. شاشة المحافظات — GEN-004

- إنشاء الشاشة وإضافتها للمشروع.
- اعتماد الحقول الأساسية الظاهرة في التصميم.
- توحيد أسماء تشغيلية لعدد من الأدوات ذات الأسماء الافتراضية.
- ربط الشاشة بقائمة البيانات الجغرافية في الشاشة الرئيسية.
- فتح الشاشة داخل تبويب ومنع تكرار فتح التبويب نفسه.
- تثبيت ظهور قسم بيانات الإنشاء والتعديل والعدادات.

**الحالة:** منفذة بصريًا ومربوطة مبدئيًا، وتحتاج اختبار تشغيل نهائي.

### 2. شاشة المديريات — GEN-005

- إنشاء الشاشة وإضافة الحقول المعتمدة.
- إضافة الدولة والمحافظة كسلسلة اختيار لتصفية البيانات.
- تصحيح عنوان الشاشة من «المدريات» إلى «المديريات».
- إعادة تفعيل `InitializeComponent()`.
- توحيد عدد من الأسماء البرمجية المهمة.
- ربط الشاشة بالشاشة الرئيسية داخل تبويب مستقل.
- تثبيت ظهور بيانات الإنشاء والتعديل والعدادات.

**الحالة:** منفذة بصريًا ومربوطة مبدئيًا، وتحتاج اختبار تشغيل نهائي.

### 3. شاشة المناطق — GEN-007

- إنشاء الشاشة وإضافة الحقول الأساسية.
- اعتماد التسلسل: الدولة ← المحافظة ← المديرية ← المنطقة.
- إعادة تفعيل `InitializeComponent()`.
- تصحيح أسماء تشغيلية مهمة، ومنها أداة اختيار المديرية وجدول المناطق.
- ربط الشاشة بالشاشة الرئيسية داخل تبويب مستقل.
- تثبيت ظهور بيانات الإنشاء والتعديل والعدادات.

**الحالة:** منفذة بصريًا ومربوطة مبدئيًا، وتحتاج اختبار تشغيل نهائي.

### 4. الشاشة الرئيسية

- ربط المحافظات والمديريات والمناطق بقائمة البيانات الجغرافية.
- منع فتح أكثر من تبويب لنفس الشاشة.
- استضافة الفورم داخل مساحة العمل دون حدود نافذة مستقلة.

### 5. معالجة مشاكل Git والموارد

- حل تعارضات الدمج في:
  - `ScreenHeaderControl.cs`
  - `FrmDashboard.Governorates.cs`
- إزالة ملف الموارد المتعارض `FrmDashboard.Governorates.resx`.
- معالجة تعارض اسم المورد `FrmDashboard.resources`.
- رفع التعديلات إلى الفرع الحالي.

### 6. التوثيق

تم إضافة أو تحديث مستندات داخل مجلد `Documentation` تشمل:

- تقرير مراجعة التسمية والربط.
- قرار توحيد تسمية وربط الشاشات الجغرافية.
- ملحق لكراسة الشاشات الجغرافية.
- هذا التقرير المرحلي.

## المتبقي قبل اعتماد المجموعة الجغرافية نهائيًا

### أولوية عاجلة

1. تنفيذ `git pull` على الجهاز المحلي ثم بناء المشروع كاملًا.
2. تشغيل الشاشات الثلاث من القائمة الرئيسية والتحقق من:
   - فتح التبويب.
   - عدم التكرار.
   - الإغلاق الصحيح.
   - ظهور بيانات الإنشاء والتعديل والعدادات.
   - عدم وجود قص في الجزء السفلي.
3. التأكد من أن آخر تعديلات GitHub لا تتعارض مع تغييرات محلية غير مرفوعة.

### استكمال المجموعة الأولى

4. مراجعة شاشة الدول `GEN-003` وفق القالب المعتمد والتأكد من سلامة أسمائها البرمجية.
5. إنشاء أو مراجعة شاشة المدن `GEN-006` وربطها بالرئيسية؛ لم يتم التحقق من اكتمالها ضمن العمل الحالي.
6. مراجعة المحافظات والمديريات والمناطق معًا للتأكد من توحيد:
   - أسماء الحاويات.
   - أسماء حقول البحث.
   - أسماء أعمدة الجداول.
   - أسماء أدوات التذييل.
   - النصوص العربية والإملاء.

### وظائف البيانات

7. تعبئة قوائم الدولة والمحافظة والمديرية وربط التصفية المتسلسلة فعليًا.
8. تنفيذ وظائف جديد، حفظ، تعديل، حذف، بحث، طباعة، تحديث، وإغلاق.
9. تنفيذ التنقل: الأول، السابق، التالي، الأخير، ومؤشر السجل.
10. ربط DataGridView بالبيانات الفعلية وإضافة جميع الأعمدة المطلوبة، بدل أعمدة المعاينة المحدودة.
11. تطبيق التحقق من الحقول الإلزامية ومنع الحفظ عند النقص.
12. تحديث قيم بيانات الإنشاء والتعديل وعدادات التعديل والطباعة من مصدر بيانات فعلي.

### الجودة والاختبارات

13. تشغيل Build للمشروع والحل كاملًا دون أخطاء أو تحذيرات حرجة.
14. اختبار العرض على دقة اللابتوب ومع تكبير Windows بنسبة 125%.
15. اختبار RTL والمحاذاة وألوان الحقول الإلزامية.
16. إضافة اختبارات قبول للشاشات المنفذة وربطها بالكراسة.
17. التقاط صور تشغيل فعلية بعد اكتمال الاختبار وإدراجها في الكراسة المعتمدة.

## المخاطر الحالية

- تعديل خاصية `Name` في وقت التشغيل لا يعادل إعادة تسمية المتغير داخل ملفات Designer؛ ما زالت بعض المتغيرات الداخلية تحمل أسماء عامة مثل `panel2` و`button1`، وتحتاج إعادة تسمية آمنة لاحقًا إذا أُريد تنظيف كامل للكود.
- لم يتم تنفيذ Build محلي بعد آخر تعديل من خلال موصل GitHub.
- وظائف البيانات ما زالت واجهات أولية وغير مرتبطة بـ API أو قاعدة بيانات.
- شاشة المدن لم تدخل ضمن المراجعة الأخيرة، لذلك لا يجوز اعتبار المجموعة الجغرافية مكتملة برمجيًا 100%.
