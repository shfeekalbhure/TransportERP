# UI-EXEC-002 — استثناء تنفيذ WinForms من بيئة المستودع

**الحالة:** معتمد  
**تاريخ الاعتماد:** 2026-08-07  
**النطاق:** `TransportERP.Desktop`

## القرار

الأصل في التنفيذ المحلي على Windows هو استخدام `Windows Forms Designer` و`Toolbox` و`Properties Window` عندما تكون متاحة.

أما إذا كان التنفيذ بواسطة مساعد يعمل مباشرة داخل مستودع Git ولا تتوفر له Visual Studio أو Windows Forms Designer، فيسمح له صراحةً بإنشاء وتعديل ملفات:

- `.cs`
- `.Designer.cs`
- `.resx`

مباشرة داخل المستودع.

## الشروط الإلزامية

1. يجب أن تكون النتيجة بصيغة WinForms القياسية وقابلة للفتح لاحقًا في Windows Forms Designer.
2. كل Control ثابت له `field declaration` صريح مستقل.
3. كل Control ثابت ينشأ مباشرة داخل `InitializeComponent()`.
4. يمنع استخدام متغيرات محلية مؤقتة أو Helper Methods جماعية لإنشاء العناصر الثابتة إذا كان ذلك يمنع مراجعة وضبط خصائص كل عنصر بصورة مستقلة.
5. تطبق خصائص الـForm والحاويات والأدوات والمقاسات والاتجاه والترتيب كما هي في مراجع الإصدار 1.13.
6. يمنع التخمين. أي بند غير محدد يسجل `غير محددة في المرجع` ولا ينشأ من الاجتهاد.
7. RTL إلزامي حيث يقرره المرجع، بما في ذلك `RightToLeft = Yes` و`RightToLeftLayout = True` وترتيب العناصر من اليمين إلى اليسار.
8. لا يجوز تغيير بنية الحاويات أو المقاسات أو خصائصها لتسهيل كتابة الكود.
9. لا يشمل هذا القرار API أو قاعدة البيانات أو العقود أو الخدمات أو منطق الأعمال إلا بتكليف مستقل.
10. عند توفر Visual Studio لاحقًا، يجب التحقق من فتح النماذج في Designer دون أخطاء.

## معالجة التعارض

أي نص سابق يحصر إنشاء الشاشة في Windows Forms Designer يفسر بأنه الأسلوب الأصلي عند توفر بيئة Visual Studio، ولا يعد مانعًا لتنفيذ تكليف صريح داخل المستودع.

هذا القرار يرفع فقط تعارض عدم توفر Designer/Toolbox/Properties Window، ولا يلغي أي مواصفات تصميمية أخرى معتمدة في الإصدار 1.13.

## قاعدة التنفيذ

عند صدور تكليف صريح بالعمل داخل المستودع، يبدأ المساعد التنفيذ مباشرةً وفق هذا القرار ولا يتوقف لمجرد عدم توفر Visual Studio أو Windows Forms Designer.
