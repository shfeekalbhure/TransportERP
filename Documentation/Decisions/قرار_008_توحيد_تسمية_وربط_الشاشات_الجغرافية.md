# القرار رقم (008) — توحيد التسمية البرمجية وربط الشاشات الجغرافية

**الحالة:** معتمد  
**التاريخ:** 2026-08-05  
**النطاق:** مشروع `TransportERP.Desktop`، المجموعة الأولى للبيانات الجغرافية.

## نص القرار

1. تعتمد الأسماء البرمجية الإنجليزية الواضحة للأدوات وفق نوع الأداة ووظيفتها، ومن أمثلتها:
   - `lbl...Title` للتسميات.
   - `txt...` لحقول النص.
   - `cmb...` لقوائم الاختيار.
   - `btn...` للأزرار.
   - `dgv...` للجداول.
   - `pnl...` للحاويات.
   - `grp...` للمجموعات.
   - `tlp...` لحاويات `TableLayoutPanel`.

2. يمنع اعتماد أسماء المصمم الافتراضية مثل `button1` و`textBox2` و`comboBox1` و`panel2` كأسماء نهائية لأداة ذات وظيفة معروفة.

3. تعتمد الشاشات الحالية بالأسماء التالية:
   - `FrmGovernorates` — المحافظات — `GEN-004`.
   - `FrmDirectorates` — المديريات — `GEN-005`.
   - `FrmAreas` — المناطق — `GEN-007`.

4. تعتمد سلسلة التصفية العملية في النماذج الحالية كما يلي:
   - المديريات: الدولة ← المحافظة ← المديرية.
   - المناطق: الدولة ← المحافظة ← المديرية ← المنطقة.

5. وجود الدولة والمحافظة في شاشة تابعة يجوز استخدامه للتصفية وتحسين تجربة المستخدم، بينما يبقى الأب المباشر هو المرجع المحفوظ وفق نموذج البيانات المعتمد لاحقاً.

6. تفتح الشاشات الفرعية داخل تبويبات مساحة العمل في `FrmDashboard`، ويمنع فتح أكثر من تبويب للشاشة نفسها.

7. لا تتكرر معلومات الشركة والفرع والسنة والمستخدم والاتصال داخل الشاشات الفرعية؛ تبقى ملكاً للشاشة الرئيسية.

8. إعادة تسمية معرفات الأدوات داخل ملفات Designer تنفذ لاحقاً بأسلوب Refactor آمن، ويجوز مؤقتاً تصحيح خاصية `Name` عند التهيئة حفاظاً على التصميم اليدوي.

## أثر القرار

- توحيد أسماء الأدوات يسهل الصيانة والربط والاختبار.
- الربط المركزي يقلل تكرار كود فتح النوافذ.
- التصفية الهرمية تمنع اختيار محافظة أو مديرية من نطاق جغرافي غير صحيح.
- لا يضيف القرار قاعدة بيانات أو API أو منطق أعمال جديداً.
