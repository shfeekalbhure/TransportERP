## 1. الحكم التنفيذي

حالة فرع العمل **صالحة للاستمرار في مراجعة شاشة الدخول ومكتبة CoreUI**، لكن لا يمكن اعتبار المرحلة مغلقة تنفيذيًا بعد؛ لأن GitHub لا يعرض أي فحص بناء أو اختبارات آلية مرتبطة بآخر Commit، كما أن نسخة المستخدم المحلية كانت تحتوي على ثلاثة تعديلات غير ملتزم بها وStash واحد، وهي حالة محلية لا تظهر داخل المستودع البعيد.

الفرع الرئيسي للمستودع مختلف عن فرع العمل؛ أحدث Commit ظاهر على الفرع الرئيسي هو:

- `fc607fc6e735f7b554f80dd9ad5d668bf50659c3`
- `Reset repository to empty project structure`

أما تحديثات شاشة الدخول وCoreUI فهي موجودة على فرع:

- `setup/initial-solution-structure`

لذلك يمنع الدمج أو النقل إلى الفرع الرئيسي قبل نجاح البناء والمراجعة البصرية.

## 2. ما تمت مراجعته

### 2.1 شاشة LOGIN-001

تم التحقق من وجود النسخة المجمعة لشاشة الدخول، وتشمل:

- `TransportERP.Desktop/Forms/FrmLogin.cs`
- `TransportERP.Desktop/Forms/FrmLogin.Designer.cs`
- `TransportERP.Desktop/Forms/FrmLogin.resx`
- تشغيل الشاشة من `TransportERP.Desktop/Program.cs`

### 2.2 عناصر CoreUI المستخدمة

شاشة الدخول تعتمد حاليًا على العناصر التالية:

- `PrimaryButton`
- `RequiredTextBox`
- `LookupComboBox`
- `TransportStatusBar`
- `UiTheme`

### 2.3 سلوك شاشة الدخول الحالي

الموجود حاليًا:

- تعبئة مؤقتة للشركة والفرع والسنة المالية.
- التحقق من الحقول الإلزامية.
- زر رئيسي واحد باسم **دخول**.
- تحديث شريط الحالة من الاختيارات الحالية.
- تصميم RTL وتعليقات عربية داخل الكود.
- رسالة مؤقتة بدل المصادقة الحقيقية.

غير الموجود حاليًا:

- ربط API فعلي.
- مصادقة حقيقية.
- تحميل الشركات والفروع من الخادم.
- إدارة جلسة مستخدم.
- فتح Dashboard بعد نجاح المصادقة.
- استعادة كلمة مرور فعلية.

## 4. ملاحظات فنية مهمة

### 4.1 تحديث شاشة الدخول ليس Commit واحدًا تاريخيًا بالكامل

تم إنشاء Commit نهائي يجمع **الحالة النهائية لمنطق الشاشة**، لكن ملفات CoreUI والمصمم أُنشئت عبر Commits سابقة على نفس الفرع. لذلك سحب الفرع بالكامل يعطي النسخة الصحيحة، أما نقل Commit الأخير وحده إلى فرع آخر فلن يكون كافيًا دون الاعتماديات السابقة.

### 4.2 لا يوجد دليل بناء بعيد

آخر Commit مجمع:

`a29f5b1f8fca5c81dbbf10721581d2fce5e612b7`

لا توجد له:

- GitHub Actions workflow runs.
- Combined status checks.

وبالتالي لا يجوز وصفه بأنه ناجح البناء من المستودع وحده. نجاح البناء يجب تأكيده محليًا عبر:

```powershell
dotnet build TransportERP.slnx
```

أو عبر `Rebuild Solution` في Visual Studio مع إظهار `0 Errors`.

### 4.3 التغييرات المحلية تمنع Pull

ظهور الرسالة:

`Cannot pull because there are uncommitted changes`

سببه وجود تعديلات محلية في:

- `FrmLogin.cs`
- `FrmLogin.Designer.cs`
- `FrmLogin.resx`

يجب حفظها في Commit مستقل إن كانت مطلوبة، أو التراجع عنها إذا كانت نسخة قديمة، ثم تنفيذ Pull. لا يجوز حذفها دون التأكد من عدم وجود عمل محلي مهم.

## 5. المخاطر الحالية

1. **مخاطر اختلاف الفروع:** الفرع الرئيسي لا يمثل فرع العمل الحالي.
2. **مخاطر الاعتماد على المصمم:** فتح WinForms Designer قد يعيد كتابة `Designer.cs` و`resx` ويخلق تعديلات محلية تلقائية.
3. **مخاطر غياب CI:** لا يوجد تحقق آلي يمنع رفع كود لا يبني.
4. **مخاطر حزم NuGet:** يوجد تحذير ثغرات دون حصر دقيق للحزم المتأثرة.
5. **مخاطر التوسع المبكر:** CoreUI بدأ قبل إغلاق شاشة الدخول بصريًا ووظيفيًا؛ يجب اختبار العناصر في شاشة فعلية قبل إضافة عناصر أخرى كثيرة.
6. **مخاطر المصادقة الوهمية:** القيم الحالية تجريبية ولا يجوز اعتبار الشاشة مرتبطة بالنظام الخلفي.

## 6. المطلوب قبل اعتماد LOGIN-001 نهائيًا

1. تنظيف التغييرات المحلية ثم سحب آخر نسخة من الفرع.
2. تنفيذ `Rebuild Solution` والتأكد من `0 Errors`.
3. تشغيل `TransportERP.Desktop` والتقاط صورة واضحة للشاشة.
4. اختبار الحالات التالية:
   - اسم مستخدم فارغ.
   - كلمة مرور فارغة.
   - عدم اختيار الشركة أو الفرع أو السنة.
   - الضغط على Enter لتنفيذ زر الدخول.
   - تغيير الشركة والفرع ومراجعة شريط الحالة.
   - تغيير حجم النافذة ضمن الحد الأدنى.
5. استخراج تقرير الحزم الضعيفة من NuGet دون تحديث عشوائي.
6. عدم إنشاء Dashboard أو ربط API حتى اعتماد شاشة الدخول بصريًا، ما لم يصدر قرار جديد صريح.
