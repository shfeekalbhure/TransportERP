# REF-008 — سجل الفجوات الحاكمة الحالية

## الحالة

`Controlled Findings Register — سجل ملاحظات محكوم`.

هذا السجل يجمع الفجوات التي تمنع وصف المرجع التنفيذي الموحد بأنه جاهز للبرمجة. لا يعني وجودها إلغاء العمل السابق؛ بل يحدد ما يجب إغلاقه قبل الترقية.

## GAP-001 — الربط الدقيق لعقد الترحيل

`W2 Exact Posting Binding — الربط الدقيق لعقد الترحيل في W2`.

الدليل الحالي يشير إلى 39 صفًا ذا أثر مالي يحتاج ربطًا صريحًا بـ`Posting Contract — عقد الترحيل` مع الصلاحية والنطاق والفترة المفتوحة و`Expected Version — الإصدار المتوقع` و`Idempotency — عدم تكرار الأثر` والذرية والتوازن وعدم تعديل الأثر المرحل.

الحالة: `BLOCKING — مانع`.

## GAP-002 — الربط الدقيق لعقد العكس

`W2 Exact Reversal Binding — الربط الدقيق لعقد العكس في W2`.

الدليل الحالي يشير إلى 60 صفًا يحتاج ربطًا صريحًا بـ`Reversal Contract — عقد العكس` مع الأصل المرحل والفترة المفتوحة والصلاحية وعدم التكرار وقيد العكس الجديد و`Rollback — الرجوع` الذري.

الحالة: `BLOCKING — مانع`.

## GAP-003 — تتبع الشاشة إلى واجهة البرمجة والصلاحية

`Current Screen → API → Permission Trace — تتبع الشاشة الحالية → واجهة البرمجة → الصلاحية`.

يجب أن يربط المرجع الموحد الشاشات ذات الصلة بالنسخة الحالية من `Screen_to_API_and_Permission_Traceability_TransportERP_V1.6.xlsx`، ولا يعتمد على أثر قديم أو مسودة.

الحالة: `BLOCKING — مانع` ضمن الشاشات الحساسة أو التنفيذية.

## GAP-004 — توزيع الحقول والإجراءات على التبويبات

`Field/Action → Tab/Area — الحقل/الإجراء → التبويب/المنطقة`.

طبقة ARCH-01R-REM-001 تغطي 8,230 حقلًا و6,282 إجراءً هيكليًا، لكنها `DERIVED_ARCHITECTURE — معمارية مشتقة`، وتحتاج مراجعة دلالية لا مجرد نجاح هيكلي.

الحالة: `REVIEW REQUIRED — مراجعة مطلوبة`، وتصبح مانعة حيث يؤثر الموضع في السلوك أو الصلاحية أو سير العمل.

## GAP-005 — عقد العمل دون اتصال والجوال

`Offline/Mobile Contract — عقد العمل دون اتصال والجوال`.

يجب لكل عملية أو حقل حساس تحديد:

- `Online / Offline Class — تصنيف الاتصال / دون الاتصال`.
- `Local Storage — التخزين المحلي`.
- `Sync Method — طريقة المزامنة`.
- `Conflict Policy — سياسة التعارض`.
- `Idempotency — عدم تكرار الأثر`.
- `Expected Version — الإصدار المتوقع`.
- `Final Authority Node — عقدة السلطة النهائية`.
- `Attachment / GPS Channels — قنوات المرفقات / تحديد المواقع`.

الحالة: `BLOCKING — مانع` قبل وصف النظام بأنه جاهز لتشغيل الفروع والجوال دون اتصال.

## GAP-006 — إغلاق البيانات وفق W1

`W1 Data Closure — إغلاق البيانات وفق W1`.

يجب ربط المفاهيم المنطقية والشاشات والكيانات والجداول والقيود والاختبارات وفق W1 الحالية، مع منع اختراع `Physical Schema — مخطط فيزيائي` خارج سلطة W1.

الحالة: `REQUIRED — مطلوب`.

## GAP-007 — الاختبارات والأدلة

الهدف النهائي:

`Requirement → Contract → Test → Evidence — المتطلب → العقد → الاختبار → الدليل`.

لا يكفي وجود تقرير يقول `PASS — نجاح` دون دليل قابل لإعادة التحقق عندما تكون النتيجة تنفيذية أو حاكمة.

الحالة: `REQUIRED — مطلوب`.

## GAP-008 — الضمان المستقل

`Independent Final Assurance — ضمان مستقل نهائي`.

بعد إغلاق الفجوات السابقة وتجميد الحزمة، يجب أن يعيد فريق مستقل التحقق قبل أي `Promotion — ترقية` إلى `Current Approved — الحالي المعتمد` أو `Ready for Programming — جاهز للبرمجة`.

الحالة: `MANDATORY FINAL GATE — بوابة نهائية إلزامية`.
