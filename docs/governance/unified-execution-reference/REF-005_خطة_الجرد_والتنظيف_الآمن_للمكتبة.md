# REF-005 — خطة الجرد والتنظيف الآمن لمكتبة TransportERP

## 1. الحالة

`Controlled Execution Plan — خطة تنفيذ محكومة`.

هذه الخطة لا تسمح بالحذف الفوري. تبدأ بالجرد والتصنيف والتحقق، ثم تنتقل إلى العزل والأرشفة وإزالة الالتباس، ولا يصل الحذف إلى أي أصل إلا بقرار لاحق موثق.

## 2. الهدف

تحويل `File Library — مكتبة الملفات` من تجمع تاريخي كبير إلى مكتبة منظمة يمكن معرفة المرجع الصحيح فيها فورًا، مع عدم فقد أي دليل أو مصدر أو تاريخ اعتماد.

## 3. المناطق الخمس المستهدفة

1. `Current Governing — الحاكم الحالي`: الملفات الحاكمة فقط.
2. `Controlled Working — العمل المحكوم`: ملفات العمل النشطة والمرشحات الحالية.
3. `Evidence & Review — الأدلة والمراجعات`: الاختبارات، تقارير الضمان، الصور، وسجلات التشغيل.
4. `Historical / Superseded — التاريخي / المستبدل`: النسخ القديمة التي لا تستخدم للتنفيذ.
5. `Quarantine / Conflict — الحجر / التعارض`: الاسم نفسه ببصمة مختلفة، هوية غير محسومة، أو سلطة غير واضحة.

## 4. قاعدة عدم الحذف

حتى انتهاء الجرد:

`DELETE = NOT AUTHORIZED — الحذف = غير مصرح`.

النسخة التي يثبت أنها مكررة لا تحذف مباشرة. تسجل العلاقة أولًا:

- `True Duplicate — نسخة متطابقة حقيقية`.
- `Controlled Copy — نسخة مضبوطة`.
- `Superseded — مستبدلة`.
- `Name Collision — تعارض اسم`.
- `Unknown Identity — هوية غير محسومة`.

## 5. حقول سجل الجرد

لكل ملف أو حزمة يجب تسجيل:

- `Artifact ID — معرف الأصل`.
- `Version ID — معرف الإصدار`.
- الاسم.
- المسار.
- النوع.
- الحجم.
- تاريخ الإنشاء والتعديل.
- `SHA-256 — البصمة` حيث يمكن حسابها أو استخراجها.
- `Authority Class — فئة السلطة`.
- `Lifecycle Status — حالة دورة الحياة`.
- `Governance Status — الحالة الحوكمية`.
- المصدر/العائلة.
- هل له نسخة أخرى بنفس الاسم؟
- هل له نسخة أخرى بنفس البصمة؟
- هل يدخل المرجع التنفيذي الموحد؟
- طريقة الاستخدام: مباشر / مشروط / دليل / أرشيف / حجر.

## 6. قواعد التكرار والتعارض

### 6.1 الاسم نفسه والبصمة نفسها

يصنف `True Duplicate — تكرار حقيقي` أو `Controlled Copy — نسخة مضبوطة` بحسب السياق. يحتفظ بالمواقع والعلاقة ولا يحذف تلقائيًا.

### 6.2 الاسم نفسه والبصمة مختلفة

يصنف `Quarantined Conflict — تعارض محجور` حتى تحديد المصدر والسلطة. لا يستخدم للتنفيذ.

### 6.3 الاسم مختلف والبصمة نفسها

يصنف `Byte-Identical Copy — نسخة متطابقة بايتيًا`. تحفظ العلاقة وقد يزال الالتباس في مرحلة لاحقة دون إسقاط الأثر.

### 6.4 الاسم مختلف والمحتوى متقارب

لا يحسم من الاسم أو البصمة. يلزم `Semantic Comparison — مقارنة دلالية` لتحديد: تكرار، تداخل جزئي، أو غرض مختلف.

## 7. ترتيب التنظيف

1. تثبيت `Source Authority Register — سجل سلطة المصادر`.
2. تحديد كل `Current Approved — حالي معتمد`.
3. عزل `Archive / Superseded — الأرشيف / المستبدل` منطقيًا.
4. عزل `Quarantine — الحجر`.
5. تحديد النسخ المتطابقة.
6. بناء `Legacy Path Map — خريطة المسارات القديمة`.
7. بناء `Master Artifact Register — سجل الأصول الرئيسي`.
8. إنشاء `Migration Dry Run — تجربة انتقال جافة` قبل أي نقل فعلي واسع.
9. بعد تحقق مستقل فقط يمكن إصدار أمر منفصل لإزالة النسخ غير اللازمة.

## 8. ما لا يجوز أثناء التنظيف

- تغيير محتوى ملف حاكم لمجرد إعادة التنظيم.
- إعادة تسمية ملف ثم فقد مساره القديم.
- دمج ملفين بالاسم فقط.
- تحويل مسودة إلى حاكم لأنها أحدث تاريخًا.
- حذف ملف مراجعة أو دليل لأن نتيجته لم تعد مطلوبة.
- خلط `V4.1R2 — V4.1R2` الخاص بالكراسة مع `R2 — R2` الخاص بهيكل المشروع أو الحزم.

## 9. شرط الدخول إلى المرجع التنفيذي الموحد

لا يدخل أي عنصر إلى المتن التنفيذي إلا إذا كان واحدًا من:

- `GOVERNING_CURRENT — حاكم حالي`.
- `PRESERVED_SOURCE — مصدر محفوظ` لا يخالف الأعلى.
- `DERIVED_ARCHITECTURE — معمارية مشتقة` موسومة ومراجعة.

أما `BENCHMARK_CANDIDATE — مرشح المقارنة` فيدخل كسجل توصيات فقط، و`EVIDENCE_ONLY — دليل فقط` يربط بالاختبارات والقرارات ولا يتحول إلى قاعدة أعمال.

## 10. حكم المرحلة

`LIBRARY CLEANUP = INVENTORY FIRST — تنظيف المكتبة = الجرد أولًا`.

`DELETION = DEFERRED — الحذف = مؤجل`.

`SAFE CLASSIFICATION = AUTHORIZED — التصنيف الآمن = مصرح`.

`QUARANTINE OF AMBIGUOUS IDENTITY = REQUIRED — حجر الهوية الملتبسة = إلزامي`.

الخطوة التالية هي تحويل الجرد التاريخي الموجود إلى `Master Artifact Register — سجل الأصول الرئيسي` قابل للتتبع، ثم مراجعة عينة مستقلة قبل أي نقل فعلي.
