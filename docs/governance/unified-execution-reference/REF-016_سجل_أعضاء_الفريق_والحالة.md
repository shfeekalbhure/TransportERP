# REF-016 — سجل أعضاء الفريق والحالة

## 1. الغرض

تثبيت التشكيل التنفيذي الوظيفي لمشروع **المرجع التنفيذي الموحد لمشروع TransportERP** على أساس **11 مقعدًا وظيفيًا مستقلًا** مستمدة من `REF-014 — ميثاق وتكليف فريق المرجع التنفيذي الموحد`.

هذا السجل لا ينشئ حسابات GitHub — جيت هب، ولا ينقل المستودع إلى Organization — منظمة، ولا يغير صلاحيات المستودع.

## 2. الهيكل الحاكم

- **Project Owner — مالك المشروع:** السلطة الحاكمة العليا، خارج المقاعد الأحد عشر.
- **Execution Team — فريق التنفيذ:** 11 مقعدًا وظيفيًا مستقلًا يعملون كفريق واحد.
- **Independent Final Assurance Review — المراجعة النهائية المستقلة:** فريق منفصل خارج المقاعد الأحد عشر.

لا يجوز لأي مقعد اعتماد مخرجاته اعتمادًا نهائيًا بنفسه.

## 4. تفسير الحالات

- `ACTIVE — نشط`: توجد حزمة عمل مفتوحة ودليل تنفيذ فعلي حديث مرتبط بالمقعد.
- `WAITING — بانتظار`: حزمة العمل مفتوحة لكن لا يوجد بعد مخرج تخصصي جديد يغلق المرحلة التالية لذلك المقعد، أو أن العمل يعتمد على مخرج سابق.
- `COMPLETE — مكتمل`: لا تستخدم إلا بعد استيفاء مخرجات المقعد كاملة وشروط الإغلاق والتحقق من التسليم.
- اكتمال `SUB-GATE — بوابة فرعية` لا يعني اكتمال المقعد بالكامل.

## 7. القواعد الحاكمة

1. لا إنشاء لحسابات GitHub — جيت هب وهمية.
2. لا نقل المستودع إلى Organization — منظمة ضمن هذا التكليف.
3. لا تعديل لصلاحيات المستخدمين أو المتعاونين ضمن هذا التكليف.
4. لا حذف أو نقل أصول قبل قرار محكوم.
5. لا اعتماد نهائي من المقاعد التنفيذية.
6. كل مصطلح إنجليزي يتبعه ترجمة عربية.
7. أي تغيير في حالة مقعد يجب أن يستند إلى دليل فعلي: ملف، سجل، نتيجة مراجعة، أو مخرج قابل للتتبع.
8. `REFERENCE ONLY — مرجع فقط` لا ينشئ متطلبًا حاكمًا.
9. `DEVELOPMENT PROPOSAL — مقترح تطوير` لا يصبح متطلبًا إلا عبر مسار تبنٍ معتمد.

## 8. التحديث المستمر

يحدث هذا السجل عند:

- بدء مخرج جديد لمقعد.
- تغير الحالة ACTIVE / WAITING / COMPLETE — نشط / بانتظار / مكتمل.
- صدور ملف أو سجل جديد.
- إغلاق أو إعادة فتح حزمة عمل أو بوابة فرعية.
- اكتشاف عائق يمنع المقعد من الاستمرار.

ولا تعتبر حالة `COMPLETE — مكتمل` صحيحة بمجرد أن تكون Issue — المهمة مفتوحة أو مغلقة؛ يلزم تحقق من المخرجات وشروط الإغلاق.
