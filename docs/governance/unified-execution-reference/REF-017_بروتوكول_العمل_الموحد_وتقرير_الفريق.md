# REF-017 — بروتوكول العمل الموحد وتقرير الفريق

## 1. القرار التنظيمي

يعمل أعضاء فريق المرجع التنفيذي الموحد الأحد عشر باعتبارهم **فريق تنفيذ واحدًا**، وليس أحد عشر فريقًا مستقلاً.

النموذج المعتمد:

`11 MEMBERS → 11 INTERNAL WORKSTREAMS → JOINT RECONCILIATION → ONE UNIFIED TEAM REPORT`

`11 عضوًا → 11 مسار عمل داخلي → مصالحة مشتركة → تقرير فريق موحد واحد`

## 2. العلاقة بين المقاعد والمسارات

كل مقعد `TEAM-01` إلى `TEAM-11` يحتفظ بمسؤوليته التخصصية المحددة في `REF-014` و`REF-016`.

لكن مخرجات كل مقعد أثناء التنفيذ تعتبر:

`INTERNAL SPECIALIST WORK REGISTER — سجل عمل تخصصي داخلي`

ولا تعتبر تقريرًا نهائيًا مستقلاً موجهاً لمالك المشروع.

## 3. آلية العمل

### أ. الفحص التخصصي
كل عضو:
- يراجع نطاقه.
- يسجل الأدلة والملاحظات.
- يفتح التعارضات والفجوات.
- يحدد ما يحتاج مصالحة مع تخصص آخر.
- يحدث حالته `ACTIVE / WAITING / COMPLETE — نشط / بانتظار / مكتمل`.

### ب. التكامل
`TEAM-01 — قائد التكامل والحوكمة` مسؤول عن:
- تجميع نتائج المسارات الأحد عشر.
- ربط التعارضات بين الأعمال والمالية والبيانات والواجهات والأمن وواجهة المستخدم والجوال والتتبع.
- منع إصدار أحكام متعارضة بين المسارات.
- توحيد سجل القرارات والتغييرات.

### ج. المراجعة المضادة
`TEAM-11 — المراجع المضاد` يراجع الناتج الموحد قبل الإصدار، ويجب أن يسجل اعتراضاته صراحة على:
- الفقد الصامت.
- التعارض غير المحسوم.
- الاستنتاج بلا دليل.
- التكرار غير المعالج.
- الربط المكسور.
- ترقية مرشح أو مسودة إلى مصدر حاكم بلا سلطة.

ولا يجوز إغلاق تقرير الفريق إذا بقي اعتراض مانع غير معالج.

## 4. المخرج التنفيذي الرسمي الوحيد للفريق

بعد اكتمال العمل الداخلي والمصالحة المشتركة يصدر الفريق وثيقة رسمية واحدة باسم:

`UNIFIED EXECUTION REFERENCE TEAM REPORT — التقرير الموحد لفريق المرجع التنفيذي`

ولا يصدر أحد عشر تقريرًا نهائيًا منفصلاً للمالك.

## 5. محتوى التقرير الموحد

يجب أن يحتوي التقرير على الأقل على:

### A. Team Completion Matrix — مصفوفة اكتمال الفريق

- `TEAM-01 Governance = COMPLETE — الحوكمة = مكتمل`
- `TEAM-02 Records = COMPLETE — السجلات = مكتمل`
- `TEAM-03 ERP/TMS = COMPLETE — أعمال تخطيط الموارد وإدارة النقل = مكتمل`
- `TEAM-04 Finance = COMPLETE — المالية = مكتمل`
- `TEAM-05 Data = COMPLETE — البيانات = مكتمل`
- `TEAM-06 API/Security = COMPLETE — واجهات البرمجة والأمن = مكتمل`
- `TEAM-07 UX/UI/CoreUI = COMPLETE — تجربة وواجهة المستخدم الأساسية = مكتمل`
- `TEAM-08 Mobile/Offline/Telematics = COMPLETE — الجوال والعمل دون اتصال والقياس عن بعد = مكتمل`
- `TEAM-09 Quality/Traceability = COMPLETE — الجودة والتتبع = مكتمل`
- `TEAM-10 Global Research = COMPLETE — البحث العالمي = مكتمل`
- `TEAM-11 Challenger Review = COMPLETE — المراجعة المضادة = مكتمل`

لا تستخدم `COMPLETE — مكتمل` إلا بدليل فعلي قابل للتتبع.

### B. Overall Status — الحالة العامة
حكم واحد باسم الفريق على حالة العمل الكلية.

### C. Blocking Findings — العوائق
كل مانع مع:
- المعرف.
- المصدر.
- التخصصات المتأثرة.
- الأثر.
- المسؤول عن المعالجة.
- حالة الإغلاق.

### D. Open Items — البنود المفتوحة
كل بند غير مانع أو مؤجل مع سبب بقائه مفتوحًا.

### E. Recommendations — التوصيات
توصيات الفريق الموحدة فقط، مع فصل:
- المتطلب الحاكم.
- المقترح التطويري.
- نتيجة البحث العالمي.

### F. Next Gate — البوابة التالية
تحديد ما إذا كان الناتج جاهزًا للانتقال إلى المراجعة النهائية المستقلة أم لا.

## 6. التقرير المستقل النهائي

`INDEPENDENT FINAL ASSURANCE REVIEW — المراجعة النهائية المستقلة` خارج الفريق الأحد عشر بالكامل.

لا يشارك فريق المراجعة المستقلة في إعداد التقرير التنفيذي الموحد، ولا يراجع عمله بنفسه.

بعد تسليم تقرير الفريق الموحد، يستلم فريق مستقل الحزمة كاملة ويصدر:

`INDEPENDENT FINAL ASSURANCE REPORT — تقرير المراجعة النهائية المستقلة`

وهو تقرير منفصل واحد.

## 7. ما يستلمه مالك المشروع

في المستوى التنفيذي النهائي، يستلم مالك المشروع تقريرين فقط:

1. `UNIFIED EXECUTION REFERENCE TEAM REPORT — التقرير الموحد لفريق المرجع التنفيذي`.
2. `INDEPENDENT FINAL ASSURANCE REPORT — تقرير المراجعة النهائية المستقلة`.

السجلات التخصصية الداخلية تبقى أدلة عمل وتتبّع، ولا تتحول إلى عبء متابعة على المالك.

## 8. حدود السلطة

- فريق الـ11 لا يعتمد عمله اعتمادًا نهائيًا.
- المراجع المضاد عضو داخل فريق التنفيذ، وليس بديلًا عن المراجع النهائي المستقل.
- المراجع النهائي المستقل لا يحتسب ضمن `TEAM-01..TEAM-11`.
- مالك المشروع يبقى السلطة العليا.

## 9. حالة التطبيق

هذا البروتوكول يطبق فورًا على:

`WP-UER-001 — تنفيذ بناء المرجع التنفيذي الموحد`

وتعتبر Issues #11 إلى #18 مسارات عمل داخلية فقط، وليست تقارير نهائية منفصلة.

## 10. صيغة الإغلاق المسموحة للفريق

إذا اكتملت جميع المسارات وأغلقت العوائق:

`UNIFIED EXECUTION REFERENCE TEAM REPORT = COMPLETE — التقرير الموحد لفريق المرجع التنفيذي = مكتمل`

`READY FOR INDEPENDENT FINAL ASSURANCE REVIEW — جاهز للمراجعة النهائية المستقلة`

وإذا بقي مانع:

`UNIFIED EXECUTION REFERENCE TEAM REPORT = BLOCKED — التقرير الموحد لفريق المرجع التنفيذي = متوقف بعوائق`

مع تسجيل العوائق صراحة.
