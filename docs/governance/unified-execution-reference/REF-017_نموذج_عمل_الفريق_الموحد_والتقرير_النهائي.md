# REF-017 — نموذج عمل الفريق الموحد والتقرير النهائي

## 1. القرار التشغيلي

يعتمد مشروع **TransportERP** نموذج فريق تنفيذي واحد مكوّن من 11 مقعدًا وظيفيًا مستقلًا، وليس 11 فرق منفصلة.

الصيغة الحاكمة:

`11 MEMBERS → 11 INTERNAL WORKSTREAMS → JOINT RECONCILIATION → ONE UNIFIED TEAM REPORT`

`11 عضوًا → 11 مسار عمل داخلي → مصالحة مشتركة → تقرير فريق موحد واحد`

## 2. التشكيل

- `TEAM-01` إلى `TEAM-11` = أعضاء/مقاعد وظيفية داخل فريق تنفيذ واحد.
- كل عضو مسؤول عن مساره التخصصي كما هو مثبت في `REF-014` و`REF-016`.
- اشتراك عضوين في حزمة عمل واحدة لا ينشئ فريقًا مستقلًا.
- Issues #11 إلى #18 هي **مسارات عمل داخلية قابلة للتتبع** وليست فرقًا منفصلة ولا تقارير نهائية مستقلة.

## 3. مخرجات كل عضو

كل عضو ينتج أثناء التنفيذ:

`INTERNAL SPECIALIST WORK LOG — سجل عمل تخصصي داخلي`

ويشمل عند الحاجة:

- ما تم فحصه.
- المصادر والملفات المستخدمة.
- النتائج.
- التعارضات.
- الفجوات.
- القرارات المقترحة.
- الأدلة.
- حالة المسار: `ACTIVE / WAITING / COMPLETE — نشط / بانتظار / مكتمل`.

هذه السجلات أدوات عمل داخلية، ولا تسلّم للمالك كتقارير نهائية منفصلة إلا عند طلبه صراحة.

## 4. دور قائد التكامل

`TEAM-01 — Integration & Governance Lead — قائد التكامل والحوكمة`

مسؤول عن:

1. جمع نتائج المسارات الأحد عشر.
2. كشف نقاط التقاطع بين التخصصات.
3. ربط التعارضات بين الأعمال والمالية والبيانات والواجهات والصلاحيات والشاشات والجوال والبحث والجودة.
4. منع وجود قرارين متضاربين لمسألة واحدة.
5. تكوين نسخة موحدة قابلة للمراجعة من نتائج الفريق.

## 5. دور المراجع المضاد

`TEAM-11 — Challenger Reviewer — المراجع المضاد`

يراجع الناتج الموحد قبل إصداره باسم الفريق، ويحاول إثبات:

- الفقد الصامت.
- التعارض غير المغلق.
- الاستنتاج بلا دليل.
- التكرار.
- فجوات السلطة.
- فجوات التتبع.
- ادعاء اكتمال غير مدعوم.

ولا يصدر المراجع المضاد اعتمادًا نهائيًا مستقلًا؛ هو جزء من فريق التنفيذ الأحد عشر.

## 6. التقرير الرسمي الوحيد لفريق التنفيذ

عند اكتمال مسارات الفريق والمصالحة والمراجعة المضادة يصدر ملف واحد باسم:

`UNIFIED EXECUTION REFERENCE TEAM REPORT — التقرير الموحد لفريق المرجع التنفيذي`

ويصدر **باسم الفريق كله** وليس باسم عضو واحد.

يجب أن يحتوي على الأقل على:

### أ. حالة الأعضاء

- `TEAM-01 Governance = COMPLETE — الحوكمة = مكتمل`
- `TEAM-02 Records = COMPLETE — السجلات = مكتمل`
- `TEAM-03 ERP/TMS = COMPLETE — أعمال النقل وتخطيط الموارد = مكتمل`
- `TEAM-04 Finance = COMPLETE — المالية = مكتمل`
- `TEAM-05 Data = COMPLETE — البيانات = مكتمل`
- `TEAM-06 API & Security = COMPLETE — واجهات البرمجة والأمن = مكتمل`
- `TEAM-07 UX/UI & CoreUI = COMPLETE — تجربة وواجهة المستخدم = مكتمل`
- `TEAM-08 Mobile/Offline/Telematics = COMPLETE — الجوال والعمل دون اتصال والتتبع = مكتمل`
- `TEAM-09 Quality & Traceability = COMPLETE — الجودة والتتبع = مكتمل`
- `TEAM-10 Global Research = COMPLETE — البحث العالمي = مكتمل`
- `TEAM-11 Challenger Review = COMPLETE — المراجعة المضادة = مكتمل`

ولا يجوز وضع `COMPLETE — مكتمل` لأي عضو دون دليل ومخرجات وشروط إغلاق قابلة للتتبع.

### ب. الحكم الموحد للفريق

- `Overall Status — الحالة العامة`
- `Blocking Findings — العوائق`
- `Open Items — البنود المفتوحة`
- `Recommendations — التوصيات`
- `Next Gate — البوابة التالية`

## 7. المراجعة النهائية المستقلة

`INDEPENDENT FINAL ASSURANCE REVIEW — المراجعة النهائية المستقلة`

تبقى خارج أعضاء الفريق الأحد عشر، ولا تشارك في إعداد تقرير الفريق التنفيذي الموحد.

بعد تسليم تقرير الفريق الموحد والحزمة المرتبطة به، يستلمها فريق مراجعة مستقل ويصدر **تقرير مراجعة مستقل واحدًا منفصلًا**.

## 8. ما يستلمه مالك المشروع

بصورة افتراضية، يستلم مالك المشروع تقريرين رئيسيين فقط:

1. `UNIFIED EXECUTION REFERENCE TEAM REPORT — التقرير الموحد لفريق المرجع التنفيذي`.
2. `INDEPENDENT FINAL ASSURANCE REVIEW REPORT — تقرير المراجعة النهائية المستقلة`.

السجلات التخصصية الداخلية تبقى متاحة للأثر والتدقيق، لكنها ليست عبئًا إداريًا على المالك.

## 9. العلاقة مع WP-UER-001

`WP-UER-001 — تنفيذ بناء المرجع التنفيذي الموحد` هو حزمة العمل الرئيسية للفريق كله.

Issues #11–#18 تبقى مسارات داخلية مرتبطة بها ولا تمثل فرقًا مستقلة.

## 10. قاعدة عدم تضخم التقارير

`ONE EXECUTION TEAM = ONE OFFICIAL TEAM REPORT`

`فريق تنفيذ واحد = تقرير رسمي واحد للفريق`

ولا ينشأ تقرير رسمي مستقل لكل تخصص إلا إذا طلب مالك المشروع ذلك صراحة أو فرضت ضرورة ضمان/تدقيق منفصلة.

## 11. السلطة

- `Project Owner — مالك المشروع` = السلطة الحاكمة العليا.
- `TEAM-01..TEAM-11` = فريق التنفيذ الموحد.
- `Independent Final Assurance Review — المراجعة النهائية المستقلة` = جهة منفصلة بعد التسليم.

هذا النموذج يسري من الآن على جميع أعمال `WP-UER-001`.
