# REF-011 — سجل الأدلة البصرية والصور لمشروع TransportERP

## الحالة

`VISUAL EVIDENCE REGISTER — سجل الأدلة البصرية`

هذا السجل لا يجعل الصورة `Business Rule — قاعدة أعمال` بذاتها، ولا يمنح أي صورة صفة `Current Approved — الحالي المعتمد` إلا إذا كان مصدرها الحاكم ينص على ذلك صراحة.

## 1. المصادر البصرية المكتشفة حتى الآن

### أ. صور التصميم الداخلية

المجلد:

`/صور التصميم`

ويحتوي حاليًا على ثلاث حزم رئيسية:

1. `صور_التصميم_TransportERP_المرحلتان_الثانية_والثالثة.zip`.
2. `حزمة_صور_المرحلة_الثانية_التهيئة_العامة_TransportERP.zip`.
3. `حزمة_صور_المرحلة_الثالثة_الأمن_والإدارة_TransportERP.zip`.

التصنيف الأولي:

`PROJECT_VISUAL_EVIDENCE — أدلة بصرية داخلية للمشروع`.

لا يتم حذفها أو دمجها قبل استخراج محتوياتها وتسجيل كل صورة على حدة وربطها بالشاشة والإصدار والبصمة.

### ب. كراسة الشاشات المعتمدة

المصدر:

`كراسة_شاشات_TransportERP_المرحلة_الأولى_الموحدة_المجموعة_الأولى_المعتمدة.docx`.

ثبت من المحتوى وجود قسم بعنوان:

`الصور المرجعية المعتمدة للشاشات العالمية`.

ويذكر صورًا مرجعية معتمدة ضمن نطاقه لشاشات منها:

- `GEN-001 — تسجيل الدخول`.
- `GEN-002 — الشاشة الرئيسية وإطار النظام`.
- `GEN-003 — الدول`.
- `GEN-004 — المحافظات`.
- `GEN-005 — المديريات`.
- `GEN-006 — المدن`.
- `GEN-007 — المناطق`.

هذه الصور تعامل وفق سلطة الوثيقة ونطاقها، ولا تعمم تلقائيًا على كل النظام.

### ج. المكتبة البصرية العالمية

المصدر المكتشف:

`TransportERP_مكتبة_صور_وفيديوهات_الشاشات_المرجعية_V3.docx`.

التصنيف:

`BENCHMARK_VISUAL_EVIDENCE — دليل بصري للمقارنة العالمية`.

الحكم الوارد في المصدر نفسه:

`VISUAL COVERAGE = CONTROLLED / PARTIAL — التغطية البصرية مضبوطة / جزئية`.

ولا توجد تغطية عامة موثقة بنسبة 100% لجميع الشاشات.

المصدر يسجل 18 مرجعًا بصريًا موثقًا في دفعة V3، ويؤكد أن الصورة القديمة لا تنسب إلى إصدار حديث دون وسم الإصدار، وأن الصور الثانوية توسم بوضوح عندما يكون الإصدار غير متحقق.

### د. سجلات البحث العالمي

المجلد:

`/TransportERP — البحث العالمي والقدرات والأدلة البصرية ومقترحات التطوير`

ويتضمن على الأقل:

- `11_سجل_الأدلة_البصرية_العالمية.csv`.
- `12_فهرس_الصور_المرجعية.csv`.
- `13_فهرس_الفيديوهات_والتوقيتات.csv`.
- `15_مصفوفة_مقارنة_الشاشات.csv`.
- `16_مصفوفة_مقارنة_التبويبات.csv`.
- `17_مصفوفة_مقارنة_الحقول.csv`.
- `18_مصفوفة_مقارنة_الإجراءات.csv`.

التصنيف:

`BENCHMARK_CANDIDATE — مرشح مقارنة` ما لم يوجد قرار تبنٍ حاكم منفصل.

## 2. مساحة العمل البصرية الجديدة

تم إنشاء المسار التالي في `File Library — مكتبة الملفات`:

`/المرجع التنفيذي الموحد لمشروع TransportERP/04_الأدلة_البصرية_والصور`

وبداخله:

- `01_صور_المشروع`.
- `02_صور_مرجعية_عالمية`.
- `03_فيديوهات_وعروض`.
- `99_صور_غير_محسومة`.

هذه المجلدات لا تعني نقل المصادر الأصلية الآن؛ هي مساحة عمل للنسخ المنظمة أو الفهارس بعد التحقق.

## 3. الحقول الإلزامية لكل صورة أو فيديو

كل أصل بصري يدخل السجل النهائي يجب أن يحمل على الأقل:

- `Visual ID — معرف الأصل البصري`.
- `Screen ID — معرف الشاشة` عند وجوده.
- `Source File — ملف المصدر`.
- `Original Path — المسار الأصلي`.
- `SHA-256 — البصمة` عند توفر الملف نفسه.
- `Artifact Type — نوع الأصل`: صورة / لقطة شاشة / فيديو / إطار فيديو / رسم توضيحي.
- `Source Class — فئة المصدر`.
- `Vendor/System — الشركة أو النظام المرجعي` عند المقارنة العالمية.
- `Product Version — إصدار المنتج` أو `VERSION NOT VERIFIED — الإصدار غير متحقق`.
- `Capture/Publication Date — تاريخ الالتقاط أو النشر` إن توفر.
- `Authority Status — الحالة الحاكمية`.
- `Visual Purpose — الغرض البصري`.
- `Visible Tabs — التبويبات الظاهرة`.
- `Visible Fields — الحقول الظاهرة`.
- `Visible Actions — الإجراءات الظاهرة`.
- `Rights Status — حالة الحقوق`.
- `Privacy Status — حالة الخصوصية`.
- `Retention Class — فئة الاحتفاظ`.
- `Reviewer Status — حالة المراجعة`.

## 4. قواعد التكرار للصور

لا يعتمد الاسم وحده.

يتم التفريق بين:

- `Exact Duplicate — نسخة مطابقة بايتيًا`.
- `Near Duplicate — نسخة شبه مطابقة`.
- `Same Screen / Different State — الشاشة نفسها بحالة مختلفة`.
- `Same Screen / Different Version — الشاشة نفسها بإصدار مختلف`.
- `Same Name / Different Bytes — الاسم نفسه وبايتات مختلفة`.
- `Different Name / Same Bytes — أسماء مختلفة وبايتات متطابقة`.

لا حذف قبل تحديد العلاقة وتثبيت المصدر والحقوق.

## 5. قاعدة السلطة البصرية

الترتيب الحاكم عند التعارض:

1. قرار مشروع حاكم صريح.
2. صورة مرتبطة بوثيقة `Current Approved — الحالي المعتمد` ضمن نطاقها.
3. مواصفة شاشة حاكمة نصيًا.
4. دليل بصري داخلي غير معتمد.
5. دليل بصري عالمي رسمي للمقارنة.
6. صورة ثانوية أو غير متحقق من إصدارها.

الصورة العالمية لا تلغي مواصفة المشروع؛ تستخدم لكشف الفجوة أو تحسين تجربة الاستخدام، ثم تحتاج `Adoption Decision — قرار تبنٍ`.

## 6. الخطوة التالية

1. استخراج فهرس محتويات حزم `/صور التصميم` دون حذف أو نقل الأصول.
2. ربط كل صورة داخلية بـ`Screen ID — معرف الشاشة` حيث يمكن إثباته.
3. إنشاء قائمة منفصلة للصور ذات الهوية غير المحسومة.
4. مطابقة صور الشاشات المعتمدة مع سجل الشاشات الحالي.
5. مراجعة فهرس الصور والفيديوهات العالمية وربطها بالشاشات والتبويبات والحقول والإجراءات ذات الصلة.
6. عدم إعلان `VISUAL COVERAGE COMPLETE — التغطية البصرية مكتملة` قبل وجود دليل فعلي لكل نطاق مطلوب.
