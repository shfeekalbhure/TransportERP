# REF-010 — سجل التكرارات والتعارضات الأولي

## الحالة

`ACTIVE CONFLICT & DUPLICATE REGISTER — سجل نشط للتعارضات والتكرارات`.

هذا السجل لا يحذف ولا ينقل أي أصل. وظيفته تثبيت ما يجب مراجعته قبل التنظيف الفعلي، وتحديث الحالات عندما يثبت الإغلاق أو يتحول التعارض إلى تكرار مادي متطابق.

## قواعد التصنيف

- `Same Name / Same SHA — الاسم نفسه والبصمة نفسها`: نسخة مادية مطابقة؛ لا حذف قبل إثبات العلاقات والمواقع.
- `Same Name / Different SHA — الاسم نفسه وبصمة مختلفة`: تعارض هوية؛ يحجر منطقيًا حتى الحسم.
- `Different Name / Same SHA — اسم مختلف وبصمة نفسها`: مرشح تكرار بايتي؛ يحفظ أثر المواقع.
- `Semantic Duplicate — تكرار دلالي`: يحتاج مقارنة محتوى، لا يكفي الاسم أو البصمة.
- `Superseded — مستبدل`: يبقى للتدقيق إذا سجل السلطة يحدد نسخة أحدث.
- `Document Number Collision — تعارض رقم الوثيقة`: رقم REF واحد مستخدم لملفات مختلفة؛ لا يعني تكرار محتوى.

## التعارضات والتكرارات المثبتة أو عالية الأولوية

### CON-001 — تتابع سجلات الملفات الحاكمة القديمة

توجد إصدارات متعددة من `سجل_الملفات_الحاكمة_Current_Approved_References` داخل التاريخ والأرشيف. المرجع الأعلى الحالي ضمن نطاق كراسة 8-8 هو V1.25 بحسب سجل السلطة الحالي.

**التصرف:** الإصدارات الأقدم `HISTORICAL_SUPERSEDED — تاريخية/مستبدلة`، ولا تستخدم للتنفيذ.

### CON-002 — كراسة 8-8 مقابل V4.1R2

V4.1R2 أوسع محتوى من ناحية عدد الشاشات والحقول والإجراءات والمفاهيم، لكنه `REMEDIATION CANDIDATE — مرشح معالجة` وليس `CURRENT APPROVED — الحالي المعتمد`.

**التصرف:** استخدام V4.1R2 كنواة محتوى للمصالحة مع طبقة السلطة من V1.25 وW1/W2/W3 فوقها، دون ترقية صامتة.

### CON-003 — V3 مقابل السلالات اللاحقة

V3 مصدر محفوظ للمعنى والتتبع، وليس سلطة أعلى من المصادر الحالية المعتمدة.

**التصرف:** `PRESERVED_SOURCE — مصدر محفوظ` مع الاحتفاظ بمعرفات المصدر.

### CON-004 — كراسة 10-10 و11-10 و14-10 مقابل كراسة 8-8

هذه السلالات لا تستبدل كراسة 8-8 تلقائيًا. 10-10 و11-10 و14-10 تحتوي دعمًا أو مرشحات أو إثراء أو مراجعات بحسب الملف.

**التصرف:** تصنيف ملفي دقيق وعدم ترقية أي منها إلى حاكم دون قرار صريح.

### CON-005 — طبقة ARCH-01R

ربط `Field→Tab — الحقل→التبويب` و`Action→Tab/Area — الإجراء→التبويب/المنطقة` ومعمارية العمل دون اتصال طبقة مشتقة لاحقة.

**التصرف:** تدخل بوسم `DERIVED_ARCHITECTURE — معمارية مشتقة` مع حفظ الاشتقاق والثقة والمراجعة، ولا يعاد وصفها كمصدر تاريخي أصلي.

### CON-006 — فجوات W2 الدقيقة — تحديث الحالة

كانت مراجعات سابقة قد سجلت فجوات في Paging — ترقيم الصفحات وLookup — الاستدعاء وHTTP Resilience — مرونة HTTP وربط بعض العقود الحساسة.

المصدر الحالي V1.25 و`تقرير_مراجعة_W2_Technical_Contracts_TransportERP_V1.6.docx` يثبتان أن `CLOSE NOW = 0 — الإغلاق الفوري = صفر` وأن W2 V1.6 هو الخط الحالي المعتمد.

**الحالة الحالية:** `RESOLVED IN CURRENT APPROVED BASELINE — مغلق في خط الأساس الحالي المعتمد` بالنسبة لفجوات W2 المسماة التي أغلقها V1.25.

**مهم:** هذا لا يغلق `FULL CROSS-DOMAIN TRACEABILITY — التتبع الكامل بين المجالات`؛ ما يزال التحقق الشامل للشاشة→الإجراء→الواجهة→الصلاحية→البيانات مطلوبًا داخل المصالحة الدلالية.

### CON-007 — هوية حزم Pre-Pilot R2

ثبت سابقًا وجود اسم نهائي واحد لحزمتين مختلفتين بايتيًا، ثم أنشئ مسار معالجة هوية مستقل.

**التصرف:** كل حزمة تخضع لـ`Package Identity — هوية الحزمة` فريدة، والنسخ المشتقة غير الحاكمة لا تحمل الاسم والهوية النهائية نفسها.

### CON-008 — مجلد توحيد الخصائص العامة

ظهرت نسخ متعددة من ملفات تحمل الاسم نفسه أو لاحقات مثل `(1)` مع أحجام متطابقة أو مختلفة.

**التصرف:** فحص البصمة والمحتوى قبل التصنيف؛ لا حذف بالاسم.

مثال مثبت في REF-011:
- GEN-016 الأصلي ونسخة `(1)` = `TRUE DUPLICATE — تكرار بايتي حقيقي`.
- ملفات ملاحظات هندسة الشاشات المتشابهة اسمًا = ليست تكرارًا بايتيًا، وتبقى `VERSION LINEAGE — سلسلة إصدارات` حتى المصالحة.

### CON-009 — صور وتصاميم بأسماء رقمية أو مولدة

المكتبة تحتوي صورًا رقمية/مولدة ونسخًا مكررة.

**التصرف:** لا حذف حاليًا. الاقتباس العالمي محصور في صور الويب الموثقة. الصور المولدة داخل ChatGPT — شات جي بي تي والنماذج الداخلية القديمة لا تدخل مكتبة الاقتباس العالمي.

المصالحة البصرية الحالية مغلقة في REF-012A/REF-020 للدفعة الحالية.

### CON-010 — مجلدات العمل المتوازية

توجد عدة مساحات عمل: `مسودة كراسة التنفيذ الاولى`، `الكراسة التنفيذية الموحدة 2026-08-15`، ومجلدات بحث ومراجعات ومعالجات متعددة.

**التصرف:** لا دمج فيزيائي الآن. المرجع التنفيذي الموحد الجديد يصبح `Working Governance Layer — طبقة حوكمة العمل` التي تشير إلى الأصول بدل نسخها جميعًا.

### CON-011 — تكرارات مادية مثبتة ضمن الأصول الحالية المعتمدة

أثبت REF-018 مجموعات `SAME LOGICAL VERSION / EXACT BYTE DUPLICATE — نفس الإصدار المنطقي / نسخة مادية مطابقة` لعدد من العقود والمصفوفات، منها:

- Posting Contract — عقد الترحيل.
- Numbering Contract — عقد الترقيم.
- Reversal Contract — عقد العكس.
- Approval Contract — عقد الاعتماد.
- Concurrency & Idempotency Contract — عقد التزامن وعدم تكرار الأثر.
- Screen Profile/Variant/Capability Matrix — مصفوفة ملف الشاشة والمتغير والقدرة.
- Field/Grid/Toolbar Architecture Matrix — مصفوفة معمارية الحقول والشبكات وأشرطة الأدوات.
- ScreenDefinition Templates — قوالب تعريف الشاشة.
- Reference Screens Matrix — مصفوفة الشاشات المرجعية.

لم يظهر ضمن المجموعات المفحوصة في REF-018 تعارض `SAME NAME / DIFFERENT SHA — الاسم نفسه / بصمة مختلفة`.

**التصرف:** لا حذف حتى اختيار النسخة المادية المرجعية وموقع الاحتفاظ.

### CON-012 — تكرارات مادية مثبتة في الدفعة المكملة V1.25

أثبت REF-021 أن النسخ المتعددة التالية متطابقة بايتيًا:

- `جدول_Traceability_TransportERP_V1.docx`.
- `خطة_التنفيذ_البرمجية_TransportERP_الموحدة_النهائية_V1.1.docx`.
- `تقرير_مراجعة_خطة_التنفيذ_TransportERP_V1.1.docx`.
- `جدول_Traceability_خطة_التنفيذ_TransportERP_V1.1.docx`.

`SAME NAME / DIFFERENT SHA — الاسم نفسه / بصمة مختلفة = 0` في هذه الدفعة.

### CON-013 — تكرارات مادية مثبتة في مجموعة الدعم الحالي

أثبت REF-023 أن النسخ المتعددة التالية متطابقة بايتيًا:

- `تقرير_تغييرات_الكراسة_الموحدة_النهائية_V1.docx`.
- `OTS_W1_001_Physical_Precision_Closure_Report_V1.docx`.
- `OTS_W1_002_UUIDv7_Physical_PK_Closure_Report_V1.docx`.

`SAME NAME / DIFFERENT SHA — الاسم نفسه / بصمة مختلفة = 0` في هذه الدفعة.

### CON-014 — تعارض أرقام REF التاريخية

تم العثور على أكثر من ملف مختلف وظيفيًا تحت REF-011 وREF-012 وREF-017.

هذا ليس تكرار محتوى، بل `DOCUMENT NUMBER COLLISION — تعارض رقم وثيقة`.

تمت المعالجة في REF-022 عبر تعيين `UER-DOC-ID — معرف وثيقة فريد` مع الحفاظ على أسماء الملفات وروابطها.

**الحالة:** `CONTROLLED — تحت السيطرة`.

## خلاصة التكرارات المادية الحالية

التكرارات التي ثبتت بالبصمة في REF-011 وREF-018 وREF-021 وREF-023 تعامل كنسخ مادية متطابقة، وليس كإصدارات منطقية جديدة.

لا يزال المطلوب قبل التنظيف:

1. اختيار `CANONICAL PHYSICAL INSTANCE — النسخة المادية المرجعية` لكل مجموعة.
2. تحديد `RETENTION LOCATION — موقع الاحتفاظ` للنسخ الأخرى.
3. ربط كل مجموعة بسجل الأصول وسلسلة الإصدارات.
4. منع حذف أي أصل قبل قرار تنظيف محكوم.

## قواعد التنظيف

1. `DELETE — الحذف` ممنوع حتى اكتمال سجل الأصول والتحقق من السلطة والبصمة.
2. `MOVE — النقل` لا يتم للأصول الحاكمة الحالية في هذه المرحلة.
3. `RENAME — إعادة التسمية` لا تتم للأصل الحاكم إلا بمعاملة حوكمة موثقة.
4. الملفات التاريخية تحفظ في موضعها أو أرشيف محكوم بعد قرار مستقل.
5. الملفات المتعارضة تنتقل لاحقًا فقط إلى `QUARANTINE — الحجر` بعد سجل قرار واضح.

## مخرج الإغلاق المطلوب لهذه المرحلة

- صفر أصل حاكم حالي غير محسوب ضمن V1.25 — تحقق هذا من حيث التغطية المنطقية في REF-021.
- صفر اسم نهائي واحد لبصمتين مختلفتين دون تصنيف داخل الدفعات التي تم فحصها — تحقق للدفعات الموثقة، ويستمر الفحص لبقية المواد التاريخية/الداعمة/المرشحة.
- سجل قرار لكل تكرار أو تعارض قبل أي تنظيف فعلي.
- إكمال النسخة المادية المرجعية وموقع الاحتفاظ قبل الانتقال لأي حذف أو نقل.
